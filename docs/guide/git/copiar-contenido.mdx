# Copiar Archivos Entre Repositorios

Git permite trabajar con repositorios locales y remotos, administrar ramas y transferir cambios entre diferentes versiones de un proyecto.

En ocasiones necesitamos copiar archivos de una rama que pertenece a otro repositorio sin fusionar ramas ni incorporar todo su historial de commits.

## Pasos a seguir

El objetivo es copiar los archivos de la rama `feature/login`, ubicada en el repositorio `frontend`, hacia la rama `feature/H001-login` del repositorio `front-app`, sin realizar una fusión (merge) entre las ramas. Para este procedimiento utilizaremos los siguientes datos:

| Elemento | Valor |
|---|---|
| Repositorio de destino | `front-app` |
| Repositorio de origen | `frontend` |
| Rama origen de la que se copiarán los archivos | `feature/login` |
| Rama destino donde se copiarán los archivos | `feature/H001-login` |
| Nombre del remoto adicional | `origen-app` |

:::warning Importante
Estos pasos solo copian el contenido de los archivos, pero no fusionan las ramas ni incorporan automáticamente el historial de commits de la rama `feature/login`.
:::

<Steps>

### Clonar el repositorio de destino

Primero, debemos clonar el repositorio en el que queremos incorporar los archivos. En este ejemplo, el repositorio de destino es `front-app`. Ejecuta el siguiente comando en la terminal:

```bash
# git clone <URL_DEL_REPOSITORIO>
git clone https://github.com/username/front-app.git
```

- `git clone` descarga una copia del repositorio remoto a tu equipo.

### Ingresar al directorio del proyecto

Una vez clonado el repositorio, debemos ubicarnos en su directorio para ejecutar comandos de Git. Ejecuta el siguiente comando en la terminal:

```bash
# cd <NOMBRE_DE_LA_CARPETA>
cd front-app
```

- `cd` es un comando de la terminal, no un comando de Git. Permite cambiar el directorio actual para ejecutar comandos dentro de la carpeta del proyecto.

:::warning Importante
Ejecutar `cd` no modifica archivos ni ramas; únicamente cambia la ubicación desde la que trabajas en la terminal.
:::

### Cambiar a la rama de destino

Ahora debemos situarnos en la rama donde queremos copiar los archivos: `feature/H001-login`. Para ello ejecutamos el siguiente comando:

```bash
# git checkout <NOMBRE_DE_LA_RAMA>
git checkout feature/H001-login
```

- `git checkout` cambia tu directorio de trabajo a la rama `feature/H001-login`.

:::warning Importante
La rama debe existir en tu repositorio local. Si todavía no existe, puedes crearla a partir de la rama remota correspondiente o desde la rama base que necesites.
:::

### Agregar el repositorio de origen como remoto

Para acceder a los archivos del repositorio `frontend`, debemos agregarlo a la configuración de nuestro repositorio local como un remoto adicional. Ejecuta el siguiente comando:

```bash
# git remote add <ALIAS> <URL_DEL_REPOSITORIO>
git remote add origin-app https://github.com/username/frontend.git
```

- `git remote add` agrega un repositorio remoto a la configuración local de Git.
- `origin-app` es el alias que utilizaremos para identificar el repositorio de origen. `origin-<NAME_ALIAS>` es una convención habitual.

:::info
El alias puede tener cualquier nombre válido. En este ejemplo utilizamos `origen-app` para distinguirlo del remoto origin, que normalmente corresponde al repositorio `front-app`.
:::

### Descargar la información de la rama de origen

Una vez configurado el remoto, debemos descargar la información de la rama `feature/login` del repositorio `frontend` ejecutando el siguiente comando:

```bash
# git fetch <ALIAS_REMOTO> <NOMBRE_DE_LA_RAMA>
git fetch origin-app feature/login
```

- `git fetch` descarga información del repositorio remoto sin fusionar sus cambios con tu rama actual.
- `origen-app` identifica el repositorio del que queremos obtener la información.
- `feature/login` indica la rama de origen que necesitamos consultar.

### Copiar los archivos de la rama de origen

Este es el paso más importante de todo el procedimiento. Después de ejecutar el siguiente comando, los archivos se copiarán de la rama remota (`feature/login`) a la rama actual (`feature/H001-login`), tomando como referencia el estado de los archivos que existen en `origen-app/feature/login`, sin cambiarte de rama.

```bash
# git checkout <referencia> -- .
# git checkout <ALIAS_REMOTE>/<NAME_BRANCH_REMOTE> -- .
git checkout origin-app/feature/login -- .
```

- `git checkout` permite recuperar archivos a partir de una referencia de Git.
- `origen-app/feature/login` identifica la referencia de origen cuyo contenido queremos recuperar.
- **`--`** separa la referencia de las rutas de archivos.
- **`.`** indica que queremos recuperar los archivos del directorio actual y sus subdirectorios.

:::warning Importante
`git checkout <referencia> -- .` El comando puede sobrescribir cambios locales en los archivos seleccionados. Antes de ejecutarlo, revisa el estado del repositorio y guarda o confirma los cambios que quieras conservar.

Además, este comando no elimina necesariamente los archivos que existen únicamente en la rama de destino. Su objetivo es recuperar las rutas seleccionadas desde la referencia de origen, no hacer que ambas ramas queden idénticas.
:::

### Revisar los cambios realizados

Después de copiar los archivos, debemos comprobar qué cambios se han producido en nuestro repositorio local. Ejecuta el siguiente comando:

```bash
git status
```

- `git status` muestra el estado del directorio de trabajo y del área de preparación de Git (*staging area*).

:::warning ¿Cuándo se utiliza?
Es recomendable ejecutarlo antes y después de copiar archivos, antes de hacer un commit y siempre que quieras saber qué cambios tienes pendientes.
:::
</Steps>

Los archivos no quedan sincronizados automáticamente: si después se modifica `feature/login`, tendrás que repetir el procedimiento o utilizar otra estrategia para incorporar los cambios nuevos.

Este procedimiento es útil cuando necesitas reutilizar archivos de otra rama o repositorio sin fusionar sus ramas ni incorporar directamente sus cambios al historial mediante un merge.
