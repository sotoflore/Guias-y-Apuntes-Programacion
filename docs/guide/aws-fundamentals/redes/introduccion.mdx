# Introducción a las redes en AWS

El término **redes** se refiere a dispositivos interconectados que pueden intercambiar datos y recursos. Las redes en la nube de AWS se componen de la infraestructura y los servicios que trabajan en conjunto para alojar sus aplicaciones, datos y cualquier otro recurso que pueda necesitar.

Las **redes en AWS** permiten conectar de forma segura y controlada los diferentes recursos y servicios que forman parte de una arquitectura en la nube, como servidores, bases de datos, aplicaciones, contenedores y servicios administrados.

El principal servicio de networking de AWS es **Amazon Virtual Private Cloud (Amazon VPC)**, que permite crear una **red virtual aislada lógicamente** dentro de AWS. Una VPC permite definir aspectos fundamentales de la red, como los rangos de direcciones IP, subredes, rutas y mecanismos de control del tráfico.

La conectividad en AWS no se limita a una única VPC. También existen servicios para conectar diferentes redes y entornos, como **VPC Peering, AWS Transit Gateway y AWS Site-to-Site VPN**. Para conexiones dedicadas entre una infraestructura local y AWS, se puede utilizar **AWS Direct Connect**.

Puedes entender las redes de AWS mediante esta estructura:

>**VPC → Subredes → Rutas → Gateways → Control de tráfico → Conectividad**

Las redes de AWS proporcionan la base para construir arquitecturas **seguras, aisladas, escalables y altamente disponibles y eficientes**, permitiendo controlar tanto **cómo se comunican los recursos** como **quién puede comunicarse con ellos**.

## 1. Componentes de las redes

El componente central es **Amazon VPC (Virtual Private Cloud)**, que permite crear una red virtual aislada dentro de AWS.

### 1.1 Amazon Virtual Private Cloud (Amazon VPC)

![icono de Amazon VPC](/icons/amazon-vpc.svg)

Una **Amazon VPC** le permite aprovisionar una sección aislada de forma lógica de la nube de AWS, donde puede lanzar recursos de AWS en una red virtual que usted defina.

![Amazon VPC](/aws/redes/redes-componentes-vpc.png)

### 1.2 Subred

Las **subredes** se utilizan para organizar los recursos y pueden ser de acceso **público** o **privado**. Por lo general, una subred privada se utiliza para contener recursos como una base de datos que almacena información de clientes o transacciones. Una subred pública se suele utilizar para recursos como un sitio web orientado al cliente.

![Subred](/aws/redes/redes-componentes-subred.png)

## 2. Componentes de redes: comprensión de las conexiones mediante diagramas

Si es su primera experiencia con la TI o la computación en nube, es posible que aún no haya trabajado con diagramas arquitectónicos. En pocas palabras, un diagrama es un esquema o mapa de su red en la nube de AWS. Puede ofrecer un panorama de cómo los usuarios o las aplicaciones acceden a los servicios, los recursos o los datos. Con un vistazo rápido, puede determinar si la red se creó para ofrecer redundancia, seguridad e incluso escalabilidad. También puede servir como esquema para que no olvide las conexiones importantes al momento de crear sus soluciones.

:::info Flujo de comunicación
Una vez configurados los componentes, los recursos se comunican según las rutas y las reglas de seguridad: el tráfico sale de la instancia, la Route Table decide hacia dónde va, y los mecanismos de seguridad (Security Group / NACL) permiten o deniegan el paso.
:::

**Puntos clave**

>- Una **VPC tiene alcance regional**: pertenece a una AWS Region y puede contener recursos distribuidos en varias Availability Zones (AZ) de esa Región.
>- Una **subnet tiene alcance de una sola Availability Zone**: cada subnet está asociada a una única AZ y no puede extenderse entre varias AZ.
>- Por lo tanto, una misma VPC puede contener múltiples subnets, distribuidas entre diferentes AZ.
>- Para diseñar arquitecturas altamente disponibles, normalmente se crean subnets en varias AZ dentro de la misma VPC.
